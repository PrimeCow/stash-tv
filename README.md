# stash-tv

An Apple TV (tvOS) client for [Stash](https://github.com/stashapp/stash), the self-hosted media organizer. Browse scenes, markers, performers, and groups from the couch with the Siri Remote.

Built in SwiftUI for tvOS 17+. No third-party dependencies — a hand-rolled URLSession GraphQL client talks to your Stash server directly.

## Features

- **Scenes** — paginated grid with your Stash saved filters as a chip strip, plus a "Recent Scenes" view.
- **Markers** — timestamped moments within scenes; tap one to start playback at that point. Saved-filter management uses Stash's `SCENE_MARKERS` mode separately from scene filters.
- **Performers** — portrait grid; opening a performer paginates their scenes and offers a "Play All" queue.
- **Groups** — collections of scenes; selecting a group plays through every scene in order via `AVQueuePlayer` auto-advance.
- **Random sort re-roll** — refresh re-seeds the `random_<n>` sort on each press, so refreshing a random-sort filter actually shuffles (Stash deterministically uses the seed for stable pagination, so the client has to roll a new one).
- **App PIN** — 4-digit lock required on every cold launch and on every return from background. Custom focus-engine numeric pad with no `TextField`/`SecureField`, so credential autofill never appears.
- **HLS playback** with API-key auth folded into the stream URL.

## Requirements

- macOS with **Xcode 16 or newer**
- The **tvOS 17 (or newer) SDK** — install from Xcode → Settings → Platforms (or Components)
- [XcodeGen](https://github.com/yonaskolb/XcodeGen) — `brew install xcodegen`
- A running [Stash](https://github.com/stashapp/stash) server reachable from the Apple TV (or Mac, if you're running in the simulator)
- An **API key** from Stash (Settings → Security → API Key) if your server requires auth

## Build and run

```bash
git clone <this-repo-url>
cd stashtv
xcodegen generate
open StashTV.xcodeproj
```

In Xcode, select the **StashTV** scheme and either:

- an **Apple TV simulator** destination → ⌘R
- a real **Apple TV** on the same network (after pairing — see below) → ⌘R

### Skipping the setup screen during development

The scheme has two pre-staged environment variables disabled by default. Tick them in **Product → Scheme → Edit Scheme… → Run → Arguments → Environment Variables**:

- `STASH_SERVER_URL` — e.g. `https://stash.example.com`
- `STASH_API_KEY` — your API key

When enabled they bypass the in-app server setup view on launch.

## Installing on a real Apple TV

1. Connect the Apple TV to the same Wi-Fi as your Mac.
2. In Xcode: **Window → Devices and Simulators** → ensure your Apple TV appears under "Devices."
3. On the Apple TV: **Settings → Remotes and Devices → Remote App and Devices → "Open Xcode"**. Enter the pairing code Xcode shows.
4. Pick your Apple TV as the destination in Xcode and ⌘R.

### Code signing and the 7-day re-install problem

Apple TV apps must be signed. You have two options:

**Free Apple ID (default for everyone with an Apple ID)**
- The provisioning profile expires every **7 days**.
- After 7 days the app silently refuses to launch on the Apple TV until you **rebuild and re-deploy from Xcode**.
- You'll also hit a hard limit of ~3 apps per Apple ID signed this way.
- Fine if your Mac is always nearby; annoying if you just want the app to keep working.

**Paid [Apple Developer Program](https://developer.apple.com/programs/) ($99/year)**
- Provisioning profile is valid for **1 year**.
- App stays installed and runs without re-deploys.
- Recommended if stash-tv is going to be a daily-driver on your Apple TV.

To set the signing team: open `StashTV.xcodeproj` → select the **StashTV** target → **Signing & Capabilities** → choose your team. The default bundle identifier is `com.paulcarroll.stashtv`; change it to a reverse-DNS prefix you control (otherwise signing will conflict if anyone else with that prefix has already used it).

## First-time setup in the app

On first launch you'll be prompted to:

1. **Create a 4-digit PIN.** Required on every subsequent cold launch and every return from background. PIN is stored in the system Keychain.
2. **Enter your Stash server URL.** Both HTTPS and HTTP work — `NSAppTransportSecurity` is wide open in Info.plist for local-network deployments. If you ship beyond your LAN you should tighten that back down.
3. **Enter your API key.** Skip if your server has no auth.

The connection test on the setup screen hits Stash's `version` query so you can confirm reachability before committing the credentials.

## Tweaking the app icon

The layered tvOS app icon + top shelf banner are generated by a Swift script:

```bash
swift tools/generate_icons.swift
```

Edit colors, the wordmark, or the play-triangle shape inside that script and re-run to regenerate all 11 PNGs (small icon 1x/2x, App Store icon 1x/2x, top shelf 1x/2x, top shelf wide 1x/2x).

## Project layout

```
StashTV/
├── StashTVApp.swift             @main entry, injects shared state
├── RootView.swift               PIN / setup / TabView routing
├── Models/                      Domain types (Scene, Marker, Performer, Group, …) + JSONValue
├── Networking/                  GraphQL client + queries
├── Configuration/               ServerConfig, FilterPreferences, KeychainStore, AppLock
└── Features/
    ├── Browse/                  Scenes tab
    ├── Markers/                 Markers tab
    ├── Performers/              Performers tab
    ├── Groups/                  Groups tab
    ├── Filters/                 Chip bar + Manage Filters sheet (shared by Scenes & Markers tabs)
    ├── Player/                  AVKit playlist player
    ├── Lock/                    PIN setup + lock screens
    └── Onboarding/              Server URL / API key setup
tools/
└── generate_icons.swift         Regenerates the layered icon + top shelf PNGs
project.yml                      XcodeGen spec — re-run `xcodegen generate` after adding/removing source files
```

The `.xcodeproj` is git-ignored. `project.yml` is the source of truth — re-run `xcodegen generate` any time you add or delete Swift files.

## Compatibility notes

stash-tv is built against the current Stash schema:

- Uses `findGroups` / `findGroup` (renamed from `findMovies` in Stash v0.27).
- Uses `Performer.alias_list` (replaced the older single-string `aliases` field).

If you're on an older Stash you may need to adjust the queries under `StashTV/Networking/Queries/`.
